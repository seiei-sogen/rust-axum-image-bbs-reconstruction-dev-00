## 実装詳細

### src/models/post.rs 🔵
```rust
//! 投稿エンティティ。旧PHP `post` テーブルと一対一対応。
use chrono::NaiveDateTime;

#[derive(Debug, Clone, sqlx::FromRow)]
pub struct Post {
    pub id: i64,
    pub title: String,
    pub text: String,
    pub image: Option<String>,
    pub regist_date: NaiveDateTime,
    pub update_date: NaiveDateTime,
}
```

### src/repository/post_repo.rs 🔵
- `pub async fn list(db, limit, offset)` → `sqlx::query_as!(Post, "SELECT id, title, text, image, regist_date, update_date FROM post ORDER BY id DESC LIMIT ? OFFSET ?", limit, offset).fetch_all(db).await?`
- `pub async fn count(db)` → `let row = sqlx::query!("SELECT COUNT(*) as cnt FROM post").fetch_one(db).await?; Ok(row.cnt as u32)`
- `pub async fn find(db, id)` → `sqlx::query_as!(Post, "... WHERE id = ?", id).fetch_optional(db).await.map_err(...)`

### sqlx のオフライン対応 🟡
- 開発時は `DATABASE_URL=sqlite://data/app.db` を設定するか、`cargo sqlx prepare` を後段で導入する。本タスクでは開発用 DB を立てて `cargo check` でクエリ検証

### テスト用 in-memory プール 🔵
- `tests/common/db.rs`（または `src/repository/post_repo.rs` 内 `#[cfg(test)] mod tests`）で以下を作る:
  ```rust
  async fn setup_memory_pool() -> sqlx::SqlitePool {
      let pool = SqlitePoolOptions::new().connect("sqlite::memory:").await.unwrap();
      sqlx::migrate!("./migrations").run(&pool).await.unwrap();
      pool
  }
  ```

### テスト 🔵
- 🔵 `test_list_returns_descending_order`: 3件投入 → `list(10, 0)` の結果が id 降順
- 🔵 `test_list_respects_limit_offset`: 5件投入 → `list(2, 2)` が3番目・2番目の2件
- 🔵 `test_count_returns_total`: 7件投入 → `count` が 7
- 🔵 `test_find_returns_none_for_missing`: 1件投入 → `find(999)` が `None`

## 単体テスト要件（TDD 観点）

- 🔵 主要正常系: list の並び順・件数制御、count、find（存在あり/なし）
- 🟡 異常系: DB 接続エラーは sqlx の SqliteError 型の問題で、ユニットテスト難易度が高いため対象外
- 🟡 境界値: limit=0 で空配列を返すケースを1件用意

### 伝える主なポイント
- `sqlx::query_as!` は `Post` の各フィールド型と SELECT 結果カラムの型を突合してくれる
- `fetch_optional` で `Option<Post>` を返すと「ない」と「DBエラー」を型で区別できる
- `:memory:` SQLite は接続ごとに新規 DB になる → プール作って `migrate!` を必ず流す
- offset / limit を u32 で受けることで負数を弾く設計
