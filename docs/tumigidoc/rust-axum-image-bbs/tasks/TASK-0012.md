## タスク概要

`src/errors.rs` にアプリ共通のエラー型 `AppError`（thiserror 派生）と `AppResult<T>` 型エイリアスを定義する。`Validation / NotFound / PayloadTooLarge / Io / Sqlx / Other` の各バリアントを揃え、`IntoResponse` を実装して HTTP ステータスと簡素なエラーページに変換する。500 系は `tracing::error!` で構造化ログを出す。既存ハンドラを `Result<_, AppError>` ベースに統一し、`?` 演算子で書き直す。 🔵

## 完了条件

- 🔵 `src/errors.rs` が作成され、`AppError` enum と `AppResult<T>` が定義
- 🔵 `AppError` のバリアントは Validation(Vec<String>) / NotFound / PayloadTooLarge / Io(#[from] std::io::Error) / Sqlx(#[from] sqlx::Error) / Other(#[from] anyhow::Error)
- 🔵 `impl IntoResponse for AppError` が以下に対応:
  - Validation → 400 + プレーンテキストでメッセージ列挙（または `IndexTemplate { errors }` 再描画）
  - NotFound → 404 + 簡素な HTML
  - PayloadTooLarge → 413
  - Io / Sqlx / Other → 500 + 簡素な HTML、`tracing::error!` 出力
- 🔵 既存の handlers (`list`, `create`) のシグネチャが `AppResult<impl IntoResponse>` に統一
- 🔵 sqlx エラー・io エラーが `?` 演算子で自動変換される
- 🔵 cargo test で AppError -> Response 変換の単体テストがグリーン（4種類）
- 🔵 不正リクエストで適切な HTTP ステータスが返る
- 🔵 500 発生時に標準出力に tracing::error! ログが出る
- 🟡 axum の DefaultBodyLimit 超過時に 413 が axum 標準で返るが、内部で AppError::PayloadTooLarge に揃えるかは設計判断

## 実装詳細

### src/errors.rs 🔵
```rust
use axum::{http::StatusCode, response::{IntoResponse, Response, Html}};
use thiserror::Error;

#[derive(Debug, Error)]
pub enum AppError {
    #[error("validation failed: {0:?}")]
    Validation(Vec<String>),

    #[error("not found")]
    NotFound,

    #[error("payload too large")]
    PayloadTooLarge,

    #[error(transparent)]
    Io(#[from] std::io::Error),

    #[error(transparent)]
    Sqlx(#[from] sqlx::Error),

    #[error(transparent)]
    Other(#[from] anyhow::Error),
}

pub type AppResult<T> = Result<T, AppError>;

impl IntoResponse for AppError {
    fn into_response(self) -> Response {
        match self {
            AppError::Validation(msgs) => (
                StatusCode::BAD_REQUEST,
                Html(format!("<ul>{}</ul>", msgs.iter().map(|m| format!("<li>{m}</li>")).collect::<String>()))
            ).into_response(),
            AppError::NotFound => (
                StatusCode::NOT_FOUND,
                Html("<h1>404 Not Found</h1>")
            ).into_response(),
            AppError::PayloadTooLarge => (
                StatusCode::PAYLOAD_TOO_LARGE,
                Html("<h1>画像サイズが大きすぎます (5MB以下)</h1>")
            ).into_response(),
            err @ (AppError::Io(_) | AppError::Sqlx(_) | AppError::Other(_)) => {
                tracing::error!(error = ?err, "internal server error");
                (StatusCode::INTERNAL_SERVER_ERROR, Html("<h1>500 Internal Server Error</h1>")).into_response()
            }
        }
    }
}
```

### handlers の書き直し 🔵
- `pub async fn list(...) -> AppResult<impl IntoResponse>`
- `?` で sqlx::Error / std::io::Error を自動変換
- validate のエラー（`Vec<String>`）はハンドラ内でテンプレ再描画して 400 を返すため、`AppError::Validation` には変換しない方針（フォーム値保持のため）

## 注意事項

- 🔵 `IntoResponse` の実装内で tracing::error! を呼ぶと、Drop されたエラー情報が必ずログに残る
- 🟡 `anyhow::Error` を Other に入れることで、ライブラリエラーの一時しのぎが効く（推奨ではないが学習用）
- 🔵 `AppError::Validation` は通常 `IntoResponse` ではなくハンドラ内で消費する。直接出る場合は 400 にフォールバック
- 🔵 関連要件: NFR-402（構造化ログ）、EDGE-003（NotFound）、EDGE-004（DBエラー）、EDGE-005（I/Oエラー）
