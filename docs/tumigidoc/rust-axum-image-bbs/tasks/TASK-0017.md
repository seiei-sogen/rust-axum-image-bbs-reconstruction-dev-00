## タスク概要

`tests/common/mod.rs` を新設し、統合テストで共通して使う非同期セットアップヘルパを実装する。in-memory SQLite (`sqlite::memory:`) で `SqlitePool` を立て、`sqlx::migrate!` でマイグレーションを当て、`tempfile::TempDir` で一時 `upload_dir` を確保し、本番と同じ構成の `axum::Router` を組み立てて返す。`tower::ServiceExt::oneshot` でリクエストを投げるためのヘルパもここに集約し、後続の TASK-0018 で各シナリオテストから再利用できるようにする。 🔵

## 実装詳細

### tests/common/mod.rs 🔵
```rust
use axum::Router;
use sqlx::sqlite::SqlitePoolOptions;
use sqlx::SqlitePool;
use std::path::PathBuf;
use tempfile::TempDir;
use rust_axum_image_bbs::{app::build_router, config::Config, state::AppState};

pub struct TestApp {
    pub router: Router,
    pub db: SqlitePool,
    pub upload_dir: TempDir,
}

pub async fn setup() -> TestApp {
    let db = SqlitePoolOptions::new()
        .max_connections(1)
        .connect("sqlite::memory:")
        .await
        .expect("connect in-memory sqlite");
    sqlx::migrate!("./migrations").run(&db).await.expect("migrate");

    let upload_dir = TempDir::new().expect("tempdir");
    let config = Config {
        database_url: "sqlite::memory:".into(),
        upload_dir: upload_dir.path().to_path_buf(),
        port: 0,
        page_size: 20,
    };
    let state = AppState { db: db.clone(), upload_dir: upload_dir.path().to_path_buf(), config };
    let router = build_router(state);
    TestApp { router, db, upload_dir }
}
```

mod common;
use tower::ServiceExt;
use axum::http::{Request, StatusCode};
use axum::body::Body;

#[tokio::test]
async fn smoke_get_root_returns_200() {
    let app = common::setup().await;
    let res = app.router
        .oneshot(Request::builder().uri("/").body(Body::empty()).unwrap())

    assert_eq!(res.status(), StatusCode::OK);
}

## 注意事項

- 🔵 `sqlx::migrate!` はコンパイル時に migrations を埋め込むため、テストでもプロダクション同じ DDL が当たる
- 🔵 `Router` を毎テスト作り直すコストは小さいので、テストごとに `setup()` を呼ぶ素直な設計でよい
- 🟡 sqlite in-memory は接続ごとに別 DB なので、`max_connections(1)` を推奨（または `:memory:?cache=shared`）
- 🟡 `tests/common/mod.rs` は単体ではバイナリにならないので「未使用関数」警告は `#[allow(dead_code)]` で抑えるとよい
