## タスク概要

`sqlx 0.8` を導入し、SQLite ファイル `data/app.db` に接続するプールを起動時に構築する。`migrations/0001_init.sql`（既存 `database-schema.sql` をコピー）を `sqlx::migrate!()` で自動適用し、`post` テーブルが起動時に必ず存在する状態を作る。 🔵

## 依存タスク

- TASK-0002（tracing が動いていること。マイグレーションログを出す）

## 完了条件

- 🔵 `Cargo.toml` に `sqlx = { version = "0.8", features = ["runtime-tokio", "sqlite", "macros", "migrate", "chrono"] }` と `chrono = { version = "0.4", features = ["serde"] }` が追加されている
- 🔵 `migrations/0001_init.sql` が作成され、`design/database-schema.sql` の CREATE TABLE 文と同等内容になっている
- 🔵 `SqlitePoolOptions::new().max_connections(5).connect_with(...)` で接続できる
- 🔵 接続オプションで `create_if_missing(true)` を有効にし、`data/app.db` が無ければ作成される
- 🔵 起動時に `sqlx::migrate!("./migrations").run(&pool).await?` が成功する
- 🔵 起動後に `sqlite3 data/app.db ".schema post"` で post テーブルが存在する
- 🔵 `.env.example` に `DATABASE_URL=sqlite://data/app.db` が記載されている
- 🟡 `sqlx-cli` でも `sqlx migrate run` が同じディレクトリを適用できる

## 実装詳細

### Cargo.toml 追加 🔵
- `sqlx = { version = "0.8", features = ["runtime-tokio", "sqlite", "macros", "migrate", "chrono"] }`
- `chrono = { version = "0.4", features = ["serde"] }`

### migrations/0001_init.sql 🔵
- `database-schema.sql` の post テーブル定義（CREATE TABLE + CHECK 制約）をそのままコピー
- 末尾のコメントブロックは省略してもよい（学習しやすさ優先）

### src/main.rs（暫定） 🔵
- `let database_url = std::env::var("DATABASE_URL").unwrap_or_else(|_| "sqlite://data/app.db".to_string());`
- `let pool = SqlitePoolOptions::new().max_connections(5).connect_with(SqliteConnectOptions::from_str(&database_url)?.create_if_missing(true)).await?;`
- `sqlx::migrate!("./migrations").run(&pool).await?;`
- `tracing::info!("migrations applied");`

### .env.example 作成 🔵
```
DATABASE_URL=sqlite://data/app.db
PORT=3000
UPLOAD_DIR=uploads
```

### data ディレクトリ 🔵
- 既存の `data/.gitkeep` を維持。`data/app.db` 自体は `.gitignore` 済み

## 注意事項

- 🔵 `sqlx 0.8` 系では features 指定が `runtime-tokio` であり `runtime-tokio-rustls` 等の SSL 系は SQLite では不要
- 🟡 `sqlx::query!` を使う場合は `DATABASE_URL` 環境変数 or `.sqlx/` オフラインキャッシュが必須。本タスクではまだクエリを書かないので保留
- 🔵 関連要件: REQ-402（SQLite 採用）、NFR-403（環境変数からの設定）
- 🟡 `data/` ディレクトリは `.gitkeep` で空状態を git 管理し、`data/app.db` は ignore
