## タスク概要

`tracing` + `tracing-subscriber` を初期化し、`tower-http::trace::TraceLayer::new_for_http()` を axum の Router に装着して、HTTP リクエストの method/uri/status が標準出力にログ出力される状態を作る。学習者が「リクエストが来た」「ステータスが何で返った」を一目で把握できる土台。 🔵

## 実装詳細

### Cargo.toml 追加 🔵
- `tracing = "0.1"`
- `tracing-subscriber = { version = "0.3", features = ["env-filter"] }`
- `tower-http = { version = "0.5", features = ["trace"] }`

### src/main.rs 編集 🔵
- main の冒頭で `tracing_subscriber::fmt().with_env_filter(EnvFilter::try_from_default_env().unwrap_or_else(|_| EnvFilter::new("info,tower_http=debug"))).init();`
- `Router::new().route(...).layer(TraceLayer::new_for_http())`
- `tracing::info!("server listening on {}", addr);` を追加

### 環境変数仕様 🔵
- `RUST_LOG` で `tracing_subscriber::EnvFilter` の挙動を切替（例: `RUST_LOG=debug` / `RUST_LOG=tower_http=trace,info`）

### 想定見出し（H2）
1. なぜ最初にロギングを入れるのか
2. `tracing` の三役（subscriber / layer / event）を整理
3. `tower-http` の TraceLayer をルーターに刺す
4. `RUST_LOG` でログレベルをコントロールする
5. 実際にリクエストを飛ばしてログを観察

### 伝える主なポイント
- `tracing` は `log` クレートよりも構造化ログ寄りであること
- `tracing-subscriber` の `EnvFilter` を使うとフィルタが書きやすい
- `TraceLayer::new_for_http()` を使うと「リクエスト開始」「終了 + ステータス」が標準で出る
- println! で済まさない理由（本番にスケールしない・構造化情報が抜けないように）

### コード例として載せる断片
- `Cargo.toml` の `[dependencies]` 追加分
- `tracing_subscriber::fmt().with_env_filter(...).init()` の3〜4行
- `Router` への `.layer()` 追加部分
- `RUST_LOG=debug cargo run` 時のログ出力例

## 注意事項

- 🟡 `tracing-subscriber` を初期化する前に `tracing` でログを呼ぶと表示されないので、main の最初に書く
- 🔵 `tower-http` の features は必ず `trace` を指定（後続で `fs` が必要になるが本タスクではまだ追加しない）
- 🟡 `EnvFilter::new("info,tower_http=debug")` のようにモジュール別レベルを設定すると初学者でもログを観察しやすい
- 🔵 関連要件: NFR-402（構造化ログによる運用可視性）
