## タスク概要

TASK-0014 の `edit_submit` ハンドラに「`delete_image=on` かつ 新画像なし」の分岐を追加する。該当時は `storage::delete_image(upload_dir, id)` で物理ファイル削除、`PostRepo::update_image_path(id, None)` で image 列を NULL に更新する。**`delete_image=on` と「新画像あり」が同時送信された場合は「画像差し替えを優先（delete_image は無視）」する仕様**。コメントで明記する。 🔵

## 依存タスク

- 🔵 ブラウザ手動: チェックボックス ON で送信 → 一覧から画像が消える

## 実装詳細

### edit_submit への分岐追加 🔵
```rust
// TASK-0014 の続き
if let Some(image) = validated.image.as_ref() {
    // 新画像あり → 差し替え（delete_image=on は無視）
    // 仕様: 画像差し替えと削除が競合した場合は差し替えを優先
    image_store::delete_image(&state.upload_dir, id).await?;
    let new_path = image_store::save_image(&state.upload_dir, id, image).await?;
    post_repo::update_image_path(&state.db, id, Some(new_path)).await?;
} else if input.delete_image {
    // 新画像なし + delete_image=on → 画像のみ削除
    image_store::delete_image(&state.upload_dir, id).await?;
    post_repo::update_image_path(&state.db, id, None).await?;
}
// それ以外（画像なし + delete_image=off）→ image 列は不変
```

### parse_multipart の delete_image 抽出 🔵
- 既に `field.name() == "delete_image"` で `field.text().await?` を受け取り、`text == "on"` で `true` にする実装が必要
- TASK-0010 で導入していなければここで追加

### PostFormInput への delete_image フィールド 🔵
- `pub delete_image: bool` がすでに interfaces.rs に定義されているため、struct と parse_multipart 両方で扱うこと

### 想定見出し（H2）
1. チェックボックスの値を Multipart で受け取る（"on" 判定）
2. `Option<String>` の NULL を SQL に流す方法
3. 競合する操作の仕様（差し替え vs 削除）の決め方
4. ストレージと DB の整合性を保つ順序
5. ファイル削除の冪等性（NotFound は無視）

### 伝える主なポイント
- HTML フォームのチェックボックスは未チェック時は送信されない → `Option<bool>` 相当の扱い
- `Option<String>` を `sqlx::query!` に渡すと NULL に変換される
- 「ユーザー入力が矛盾するケース」をどう仕様化するか（学習者目線で1つに決めて明文化）
- 削除処理は「失敗しても警告のみ」「成功しても何もなくてもOK」という冪等性が重要

### コード例として載せる断片
- edit_submit の if-else 分岐部分（差し替え優先のコメント付き）
- `update_image_path(id, None)` の呼び出し
- テスト「delete_image=on で NULL になる」
