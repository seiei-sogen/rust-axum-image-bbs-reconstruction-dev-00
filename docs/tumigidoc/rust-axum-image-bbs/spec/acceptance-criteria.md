## REQ-001 / REQ-002 / REQ-012: 投稿一覧の表示 🔵

**信頼性**: 🔵 *旧PHP DBImgbbs::SelectImgbbsAll + ヒアリング*

### Given（前提条件）
- `post` テーブルにレコードが N 件存在する
- 一部レコードに画像、一部に画像なし

### When（実行条件）
- `GET /` または `GET /?page=1` にアクセスする

### Then（期待結果）
- HTTP 200 が返る
- レスポンスHTMLに id 降順で投稿カードが最大20件含まれる
- 各カードに `title`、`text`、`regist_date` が表示される
- 画像があるカードには `<img src="img/uploads/{id}.{ext}">` が、ないカードには `<img>` が含まれない

### テストケース

#### 正常系

- [ ] **TC-001-01**: 投稿が0件 🟡
  - **入力**: `GET /`
  - **期待結果**: 200。空状態メッセージが表示される
  - **信頼性**: 🟡 *UX妥当性*

- [ ] **TC-001-02**: 投稿が1件（画像あり） 🔵
  - **入力**: `GET /`、レコード1件挿入
  - **期待結果**: そのカードに画像、タイトル、本文、日付が含まれる
  - **信頼性**: 🔵 *旧PHP挙動*

- [ ] **TC-001-03**: 投稿が25件 🔵
  - **入力**: `GET /`
  - **期待結果**: 1ページ目に id 降順の20件、26件目以降は2ページ目に
  - **信頼性**: 🔵 *ヒアリング(ページング20件)*

- [ ] **TC-001-04**: 画像なし投稿の表示 🔵
  - **入力**: `image=NULL` のレコード
  - **期待結果**: `<img>` タグは出力されない
  - **信頼性**: 🔵 *旧PHP `if(empty($row[3]))` より*

#### 異常系

- [ ] **TC-001-E01**: 不正な page 値 🟡
  - **入力**: `GET /?page=-1`、`GET /?page=abc`
  - **期待結果**: 400 もしくは 1ページ目にフォールバック
  - **信頼性**: 🟡 *妥当な実装方針*

## REQ-003 / REQ-004 / REQ-005 / REQ-006: 投稿の作成 🔵

**信頼性**: 🔵 *旧PHP index.php + DBImgbbs::Insert系*

### Given（前提条件）
- `post` テーブル、`img/uploads/` ディレクトリが存在する

### When（実行条件）
- `POST /posts` に `multipart/form-data` で `title`、`text`、`image` を送信

### Then（期待結果）
- レコードが1件 INSERT される
- 画像があれば `img/uploads/{新規id}.{ext}` に保存され、`image` カラムが更新される
- 成功レスポンス（200 + 成功メッセージ、または 303 リダイレクト）

### テストケース

#### 正常系

- [ ] **TC-004-01**: title + text + 画像（jpg） 🔵
  - **入力**: title="テスト" / text="本文" / image=test.jpg(100KB)
  - **期待結果**: レコード作成、`img/uploads/{id}.jpg` 保存、`image` カラム更新
  - **信頼性**: 🔵 *旧PHP挙動*

- [ ] **TC-004-02**: title + text のみ（画像なし） 🔵
  - **入力**: image フィールド未送信
  - **期待結果**: レコード作成、`image` は空文字 or NULL、ファイル保存なし
  - **信頼性**: 🔵 *旧PHP `$_FILES['image']['error'] == UPLOAD_ERR_OK` 分岐より*

- [ ] **TC-004-03**: png 画像 🔵
  - **入力**: 有効な png
  - **期待結果**: `img/uploads/{id}.png` で保存
  - **信頼性**: 🔵 *バリデーションヒアリング*

- [ ] **TC-004-04**: gif 画像 🔵
  - **入力**: 有効な gif
  - **期待結果**: `img/uploads/{id}.gif` で保存
  - **信頼性**: 🔵 *バリデーションヒアリング*

#### 異常系

- [ ] **TC-004-E01**: title 空 🔵
  - **入力**: title=""
  - **期待結果**: 400相当、エラー「タイトルは必須です。」、レコード未作成、ファイル未保存
  - **信頼性**: 🔵 *旧PHP index.php 14-15行 より*

- [ ] **TC-004-E02**: title 51文字 🔵
  - **入力**: title="あ"×51
  - **期待結果**: 400相当、エラー「タイトルは50文字までにしてください。」
  - **信頼性**: 🔵 *旧PHP index.php 16-18行 より*

- [ ] **TC-004-E03**: text 501文字 🔵
  - **入力**: text="あ"×501
  - **期待結果**: 400相当、エラー「本文は500文字までにしてください。」
  - **信頼性**: 🔵 *旧PHP index.php 20-22行 より*

- [ ] **TC-004-E04**: 許可外MIME（pdf） 🔵
  - **入力**: image=evil.pdf
  - **期待結果**: 400相当、エラー「画像は.jpg、.gif、.pngのいずれかにしてください。」
  - **信頼性**: 🔵 *旧PHP index.php 40-49行 + NFR-102*

- [ ] **TC-004-E05**: 5MB超 🔵
  - **入力**: 6MB の jpg
  - **期待結果**: 400相当、サイズ超過エラー、レコード未作成
  - **信頼性**: 🔵 *EDGE-001*

- [ ] **TC-004-E06**: 0バイト画像 🟡
  - **入力**: 0バイト jpg
  - **期待結果**: 400相当、エラー
  - **信頼性**: 🟡 *EDGE-103*

- [ ] **TC-004-E07**: 偽装MIME（pdf→.jpg にリネーム） 🔵
  - **入力**: 中身pdf・拡張子.jpg
  - **期待結果**: ファイル先頭バイト判定で拒否、400
  - **信頼性**: 🔵 *NFR-102 (マジックナンバー判定)*

#### 境界値

- [ ] **TC-004-B01**: title 1文字 🔵
  - **入力**: title="a"
  - **期待結果**: 受理、レコード作成
  - **信頼性**: 🔵 *EDGE-101*

- [ ] **TC-004-B02**: title 50文字 🔵
  - **入力**: title="あ"×50
  - **期待結果**: 受理、レコード作成
  - **信頼性**: 🔵 *EDGE-101*

- [ ] **TC-004-B03**: text 0文字 🔵
  - **入力**: text=""
  - **期待結果**: 受理（旧PHPでも空のtextは許容）
  - **信頼性**: 🔵 *EDGE-102 / 旧PHP挙動*

- [ ] **TC-004-B04**: text 500文字 🔵
  - **入力**: text="あ"×500
  - **期待結果**: 受理
  - **信頼性**: 🔵 *EDGE-102*

- [ ] **TC-004-B05**: 画像5MBちょうど 🟡
  - **入力**: 5MB（5,242,880 byte）jpg
  - **期待結果**: 「5MB以下」が境界含むか含まないかを定義（今回は5MBを含む = 受理）
  - **信頼性**: 🟡 *仕様判断・要明文化*

## REQ-008 / REQ-009 / REQ-104: 投稿の編集 🔵

**信頼性**: 🔵 *旧PHP admin_edit.php + DBImgbbsAdmin::UpdateImgbbs より*

### Given（前提条件）
- 編集対象のレコード（id=N）が存在する

### When（実行条件）
- `GET /posts/{id}/edit` で編集画面表示
- `POST /posts/{id}/edit` で更新リクエスト

### Then（期待結果）
- GET時: 現在の title / text / image が初期表示される
- POST時: バリデーション合格でレコード更新、画像が選択されていれば置換、`update_date` が更新される

### テストケース

#### 正常系

- [ ] **TC-009-01**: title のみ変更 🔵
  - **入力**: `POST /posts/1/edit` title="新タイトル"
  - **期待結果**: レコードの `title` のみ更新、image は維持、update_date 更新
  - **信頼性**: 🔵 *旧PHP DBImgbbsAdmin::UpdateImgbbs より*

- [ ] **TC-009-02**: 画像を差し替え 🟡
  - **入力**: 新しい jpg ファイル
  - **期待結果**: `img/uploads/{id}.jpg` が上書き、image カラムは新拡張子なら更新
  - **信頼性**: 🟡 *REQ-104*

- [ ] **TC-009-03**: 画像を削除 🟡
  - **入力**: `delete_image=on`
  - **期待結果**: image を NULL に、ファイル削除
  - **信頼性**: 🟡 *REQ-103*

#### 異常系

- [ ] **TC-009-E01**: 存在しないID 🟡
  - **入力**: `GET /posts/9999/edit`
  - **期待結果**: 404
  - **信頼性**: 🟡 *EDGE-003*

- [ ] **TC-009-E02**: title 51文字 🔵
  - **入力**: title="あ"×51
  - **期待結果**: 400相当、エラーメッセージとともに編集画面再表示、入力値保持、レコード未更新
  - **信頼性**: 🔵 *旧PHP admin_edit.php 18-37行 より*

## REQ-010 / REQ-011 / REQ-102: 投稿の削除 🔵

**信頼性**: 🔵 *旧PHP admin_list.php msgDelete + DBImgbbsAdmin::DeleteImgbbs より*

### Given（前提条件）
- 削除対象のレコード（id=N）が存在し、画像ファイルもある

### When（実行条件）
- 一覧画面で「削除」ボタンを押し、confirm でOKを選ぶ
- `POST /posts/{id}/delete` がサーバに送信される

### Then（期待結果）
- レコードが削除され、対応する画像ファイルも削除される
- 一覧画面にリダイレクト、該当行が消えている

### テストケース

#### 正常系

- [ ] **TC-010-01**: 画像あり投稿の削除 🔵
  - **入力**: `POST /posts/5/delete`
  - **期待結果**: レコード削除、`img/uploads/5.jpg` 削除、303 → `/`
  - **信頼性**: 🔵 *REQ-010 + REQ-011*

- [ ] **TC-010-02**: 画像なし投稿の削除 🔵
  - **入力**: `POST /posts/6/delete`（image=NULL）
  - **期待結果**: レコード削除、ファイル削除はスキップ、エラーにならない
  - **信頼性**: 🔵 *REQ-010*

#### 異常系

- [ ] **TC-010-E01**: 存在しないID 🟡
  - **入力**: `POST /posts/9999/delete`
  - **期待結果**: 404
  - **信頼性**: 🟡 *EDGE-003*

- [ ] **TC-010-E02**: GETメソッドで送信 🟡
  - **入力**: `GET /posts/5/delete`
  - **期待結果**: 405 Method Not Allowed（または404）。削除されない
  - **信頼性**: 🟡 *NFR-105 (旧PHPは GET 受け付けていたが改善)*

## 非機能要件テスト

### NFR-001: パフォーマンス 🟡

**信頼性**: 🟡 *学習用途の妥当な目標値*

- [ ] **TC-NFR-001-01**: 100件規模の一覧表示
  - **測定項目**: サーバ応答時間（TTFB）
  - **目標値**: ローカル環境で500ms以下
  - **測定条件**: SQLite + 100レコード + 単一クライアント
  - **信頼性**: 🟡 *妥当な目標*

### NFR-101: SQLインジェクション対策 🔵

**信頼性**: 🔵 *必須要件*

- [ ] **TC-NFR-101-01**: SQLインジェクション試行
  - **検証内容**: title に `'); DROP TABLE post; --` を入力して投稿
  - **期待結果**: 該当文字列がそのまま title として保存され、`post` テーブルは破壊されない
  - **信頼性**: 🔵 *sqlx クエリマクロ使用前提*

### NFR-102: MIMEタイプ検査 🔵

**信頼性**: 🔵 *旧PHP `finfo_file` + ヒアリング*

- [ ] **TC-NFR-102-01**: 拡張子偽装画像の拒否
  - **検証内容**: `evil.exe` を `image.jpg` にリネームしてアップロード
  - **期待結果**: マジックナンバー判定で拒否、400相当
  - **信頼性**: 🔵 *NFR-102*

### NFR-103: パストラバーサル対策 🟡

**信頼性**: 🟡 *妥当な追加*

- [ ] **TC-NFR-103-01**: パストラバーサル試行
  - **検証内容**: ファイル名 `../../etc/passwd` でアップロード
  - **期待結果**: ファイル名は `{id}.{許可拡張子}` 形式で再構築されるため、相対パスが効かない
  - **信頼性**: 🟡 *NFR-103*

### NFR-104: XSS対策 🟡

**信頼性**: 🟡 *Askama 自動エスケープに依存*

- [ ] **TC-NFR-104-01**: title に `<script>alert(1)</script>` 投稿
  - **検証内容**: 一覧表示時にエスケープされて出力されるか
  - **期待結果**: `&lt;script&gt;...&lt;/script&gt;` として表示。実行されない
  - **信頼性**: 🟡 *NFR-104*
