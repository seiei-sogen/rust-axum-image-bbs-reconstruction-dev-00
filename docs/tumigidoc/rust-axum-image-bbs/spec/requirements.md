# rust-axum-image-bbs 要件定義書

**作成日**: 2026-05-22

## 概要

Rust初心者の学習目的で、昔PHPで作った画像掲示板を Rust + axum にリプレイスする。
旧PHP版の機能のうちユーザー画面のCRUD（投稿一覧・投稿作成・編集・削除）を再現し、ログイン・管理者機能は今回のスコープから外す。
実装過程はステップごとに区切ってZenn記事として発表する想定で、ソースコードには初学者向けの丁寧な日本語コメントを記述する。

## 機能要件（EARS記法）

**【信頼性レベル凡例】**:
- 🔵 **青信号**: shiyou.md・旧PHPソース・ユーザヒアリングを参考にした確実な要件
- 🟡 **黄信号**: 旧PHPソース・shiyou.mdから妥当な推測による要件
- 🔴 **赤信号**: 上記資料にない推測による要件

### 通常要件

- **REQ-001**: システムは、トップページにアクセスされた時、投稿一覧（id降順）を表示しなければならない。 🔵 *旧PHP index.php + DBImgbbs::SelectImgbbsAll より*
- **REQ-002**: システムは、各投稿について `画像（存在する場合）`・`タイトル`・`本文`・`投稿日時` を表示しなければならない。 🔵 *旧PHP DBImgbbs.php 58-83行より*
- **REQ-003**: システムは、投稿フォーム（タイトル / 本文 / 画像）を画面上に表示しなければならない。 🔵 *旧PHP index.php フォーム部分より*
- **REQ-004**: システムは、投稿フォームが送信され入力が正常な場合、`post` テーブルに新規レコードをINSERTしなければならない。 🔵 *旧PHP DBImgbbs::InsertImgbbs より*
- **REQ-005**: システムは、画像ファイルが添付されていた場合、新規発行された投稿ID `{id}` を使い `img/uploads/{id}.{拡張子}` にファイルを保存しなければならない。 🔵 *旧PHP DBImgbbs::UpdateInsertImgbbs より*
- **REQ-006**: システムは、画像保存完了後、対応するレコードの `image` カラムに画像の相対パスを更新しなければならない。 🔵 *旧PHP DBImgbbs::UpdateInsertImgbbs より*
- **REQ-007**: システムは、投稿一覧の各行に「編集」「削除」ボタンを表示しなければならない。 🔵 *ヒアリングMust Have / 旧PHP admin_list.php より*
- **REQ-008**: システムは、編集画面の表示要求を受けた場合、指定IDの投稿を取得し、編集フォームに既存値を初期表示しなければならない。 🔵 *旧PHP admin_edit.php より*
- **REQ-009**: システムは、編集フォームの送信を受けた場合、`post` テーブルの `title`・`text`（および画像が差し替えられた場合 `image`）と `update_date` を更新しなければならない。 🔵 *旧PHP DBImgbbsAdmin::UpdateImgbbs より*
- **REQ-010**: システムは、削除要求を受けた場合、指定IDのレコードを `post` テーブルから削除しなければならない。 🔵 *旧PHP DBImgbbsAdmin::DeleteImgbbs より*
- **REQ-011**: システムは、レコード削除時に対応する画像ファイルが存在する場合、`img/uploads/` 配下の該当ファイルを削除しなければならない。 🟡 *旧PHPは画像ファイルを残していたが、孤児ファイル防止のため妥当な追加と判断*
- **REQ-012**: システムは、投稿一覧をページネーション付きで表示しなければならない（1ページ20件、id降順）。 🔵 *ヒアリングでページング追加を選択*
- **REQ-013**: システムは、`/img/uploads/` 配下のアップロード済み画像を静的ファイルとして配信しなければならない。 🔵 *旧PHPと同等の閲覧手段を提供するため*

### 条件付き要件

- **REQ-101**: 投稿が0件の場合、システムは「投稿がまだありません」のような空状態メッセージを表示しなければならない。 🟡 *UX上妥当な追加*
- **REQ-102**: 削除ボタンが押下された場合、システムはクライアント側で確認ダイアログ（例: `confirm`）を表示し、ユーザーがOKを選んだ場合のみ削除リクエストを送信しなければならない。 🔵 *旧PHP admin_list.php msgDelete関数 + ヒアリングMust Haveより*
- **REQ-103**: 編集画面で「画像を削除」が選択され送信された場合、システムは該当投稿の `image` を NULL に更新し、対応するファイルを削除しなければならない。 🟡 *旧PHP admin_edit.php に該当チェックボックスがあったが処理は未実装。今回は実装する妥当な拡張*
- **REQ-104**: 編集時に新しい画像が選択されアップロードされた場合、システムは新しい画像を `img/uploads/{id}.{拡張子}` で上書き保存しなければならない。 🟡 *Updateの自然な要件として*

### 状態要件

- **REQ-201**: バリデーションエラーが発生している間、システムは入力値を保持したまま、エラーメッセージとともに投稿フォームを再表示しなければならない。 🟡 *旧PHPは入力値保持しなかったが、UX上妥当な改善*
- **REQ-202**: 投稿成功直後、システムは成功メッセージを表示しなければならない（例: PRG パターンでリダイレクト後に表示）。 🔵 *旧PHP index.php の `$_success_text` 動作より*

### オプション要件

- **REQ-301**: システムは、REST APIエンドポイント（JSONを返す）を提供してもよい。 🔴 *ヒアリングで「画面のみ」を選択したため今回は対象外。将来の拡張余地として残す*

### 制約要件

- **REQ-401**: システムは、Webフレームワークとして `axum` を使用しなければならない。 🔵 *shiyou.md 指定*
- **REQ-402**: システムは、データベースとして SQLite を使用し、DBクライアントには `sqlx` を使用しなければならない。 🔵 *ヒアリング結果*
- **REQ-403**: システムは、テンプレートエンジンとして `Askama` を使用しなければならない。 🔵 *ヒアリング結果*
- **REQ-404**: システムは、アップロード画像をローカルファイルシステム（`img/uploads/`）に保存しなければならない。 🔵 *ヒアリング結果 / 旧PHPと同方針*
- **REQ-405**: ログイン・ユーザー認証機能は今回のスコープに含めない。 🔵 *shiyou.md「ログインやユーザーも一旦なくてよい」*
- **REQ-406**: 管理者向け画面・権限制御は今回のスコープに含めない。ユーザー画面に編集・削除を集約する。 🔵 *shiyou.md「管理者とかは一旦なくてよい」*
- **REQ-407**: ソースコードには初学者向けに日本語で詳細なコメントを記述しなければならない（特に所有権・`Result`・`async/await` 等のRust特有概念）。 🔵 *shiyou.md「コメントを丁寧に」+ ヒアリング*
- **REQ-408**: 実装過程はZenn記事として発表できるよう、ステップ単位で意味のあるコミット粒度で進めなければならない。 🔵 *shiyou.md「ステップごとにZennの記事」*

## 非機能要件

### パフォーマンス

- **NFR-001**: トップページ（投稿一覧）のサーバ側応答時間は、ローカル環境かつ100件規模のデータで500ms以下を目標とする。 🟡 *学習用途として妥当な推測*
- **NFR-002**: 同時アクセス数は学習用途として1〜10程度を想定し、それを超える負荷試験は要件外とする。 🟡 *学習用途として妥当な推測*

### セキュリティ

- **NFR-101**: SQLクエリは sqlx のクエリマクロまたはバインドパラメータを使い、SQLインジェクションを防がなければならない。 🔵 *旧PHPでもプリペアドステートメントを使用 + 必須要件*
- **NFR-102**: アップロードされた画像は、ファイル先頭バイト（マジックナンバー）または `infer` クレートでMIMEを判定し、`image/jpeg`・`image/gif`・`image/png` 以外は拒否しなければならない。 🔵 *旧PHP `finfo_file` 相当 + バリデーションヒアリング*
- **NFR-103**: アップロードファイル名はユーザー入力をそのまま使用せず、`{id}.{許可された拡張子}` 形式で再構築しなければならない（パストラバーサル防止）。 🟡 *旧PHPでも `{id}.{ext}` 方式 + セキュリティ妥当性*
- **NFR-104**: テンプレート出力ではエスケープを有効にし、XSSを防がなければならない（Askamaはデフォルトで自動エスケープ）。 🟡 *Askamaのデフォルト挙動を活用*
- **NFR-105**: 投稿作成・編集・削除はPOSTメソッドで受け付け、GETでは状態変更を行ってはならない。 🟡 *REST/HTTPの原則。旧PHP `admin_delete.php?id=` は GET だったが今回は改善*

### ユーザビリティ

- **NFR-201**: 旧PHP版と同等のUI体験（Bootstrapベースのレイアウト・投稿フォーム・一覧）を提供しなければならない。 🔵 *ヒアリング結果*
- **NFR-202**: バリデーションエラーは画面上部または該当フィールド付近に日本語で表示しなければならない。 🔵 *旧PHP index.php の `$_valid_text` より*
- **NFR-203**: 削除操作は誤操作防止のため確認ダイアログを必須としなければならない。 🔵 *旧PHP admin_list.php msgDelete + ヒアリングMust Have*

### 学習・保守性

- **NFR-301**: ソースコードはモジュール単位（例: `handlers/`、`models/`、`templates/`）に分割し、各モジュールの役割を初学者がトップコメントで把握できるようにしなければならない。 🟡 *学習目的として妥当*
- **NFR-302**: 重要な型・関数には Rust の所有権・ライフタイム・Result/Option の使い方を補足する日本語コメントを付けなければならない。 🔵 *shiyou.md + ヒアリング*
- **NFR-303**: 単体テスト・統合テストを `cargo test` で実行できる状態にしなければならない。 🔵 *ヒアリング結果*

### 運用

- **NFR-401**: Dockerfile と docker-compose（または相当ファイル）を提供し、`docker compose up` でアプリケーションが起動できなければならない。 🔵 *ヒアリング結果*
- **NFR-402**: ログには `tracing` クレートを使用し、リクエスト単位の構造化ログを出力しなければならない。 🔵 *ヒアリング結果*
- **NFR-403**: 環境変数（`DATABASE_URL`、`UPLOAD_DIR`、`PORT` 等）で設定を切り替えられなければならない。 🟡 *Docker化のための標準的な要件*

## Edgeケース

### エラー処理

- **EDGE-001**: 画像ファイルサイズが上限（5MB）を超えた場合、システムはエラーメッセージを表示し、レコードは作成してはならない。 🔵 *ヒアリングで5MB上限を採用*
- **EDGE-002**: 画像のMIMEタイプが許可されたもの（jpg/gif/png）以外だった場合、システムはエラーメッセージを表示し、レコードは作成してはならない。 🔵 *旧PHP + バリデーションヒアリング*
- **EDGE-003**: 存在しないIDの編集・削除リクエストを受けた場合、システムは 404 を返さなければならない。 🟡 *REST的に妥当*
- **EDGE-004**: DB接続エラーが発生した場合、システムは 500 を返しエラーログを出力しなければならない。 🟡 *tracingログ要件と整合*
- **EDGE-005**: 画像保存先ディレクトリへの書き込みが失敗した場合、システムはトランザクションをロールバック（または作成済みレコードを削除）し、エラーを返さなければならない。 🟡 *データ整合性の確保*

### 境界値

- **EDGE-101**: タイトル0文字は拒否、1〜50文字は受理、51文字以上は拒否しなければならない。 🔵 *旧PHP index.php より*
- **EDGE-102**: 本文は0文字（空）を許容し、500文字までは受理、501文字以上は拒否しなければならない。 🔵 *旧PHP index.php より*
- **EDGE-103**: 画像ファイルが空ファイル（0バイト）の場合は拒否しなければならない。 🟡 *妥当な追加*
- **EDGE-104**: 画像未添付（`image` フィールド空）の投稿も許容しなければならない。 🔵 *旧PHP index.php `$_FILES['image']['error'] == UPLOAD_ERR_OK` 分岐より*

### 入力サニタイズ

- **EDGE-201**: タイトル・本文に含まれる HTML 特殊文字（`<`、`>`、`&`、`"`）は表示時にエスケープされなければならない。 🟡 *Askamaの自動エスケープに依存*
