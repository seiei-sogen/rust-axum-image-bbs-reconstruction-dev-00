## エピック1: 投稿の閲覧

### ストーリー 1.1: 投稿一覧を見る 🔵

**信頼性**: 🔵 *旧PHP index.php + ヒアリング Must Have より*

**私は** 掲示板の閲覧者 **として**
**投稿された画像・タイトル・本文・日付を一覧で見たい**
**そうすることで** 他のユーザーがどんな投稿をしているか把握できる

**関連要件**: REQ-001, REQ-002, REQ-012, REQ-013

**詳細シナリオ**:
1. トップページ（`/`）にアクセスする
2. 投稿一覧が id 降順（新しい順）に表示される
3. 各投稿カードに画像（あれば）、タイトル、本文、投稿日時が表示される
4. 1ページに20件まで表示され、それ以上は次ページへのリンクで遷移できる

**前提条件**:
- データベースに `post` テーブルが存在し、初期データまたは投稿済みデータが入っている
- 画像ファイルが `img/uploads/` 配下に存在する

**制約事項**:
- 1ページ最大20件
- ページパラメータは `?page=N`（1始まり）

**優先度**: Must Have

### ストーリー 1.2: 投稿が0件の時の挙動 🟡

**信頼性**: 🟡 *旧PHPは特に空状態の制御なし。UX上妥当な追加*

**私は** 初訪問の閲覧者 **として**
**まだ投稿が無い時に分かりやすいメッセージを見たい**
**そうすることで** 画面が壊れているのではなく単に投稿がないだけだと理解できる

**関連要件**: REQ-101

**詳細シナリオ**:
1. データベースに投稿が1件もない状態でトップページにアクセス
2. 「投稿がまだありません」のような空状態メッセージが表示される
3. 投稿フォームは引き続き表示される

**優先度**: Should Have

**備考**: 旧PHPでは何も表示されないだけだった。学習目的として上質な実装にする。

## エピック2: 投稿の作成

### ストーリー 2.1: テキストと画像を投稿する 🔵

**信頼性**: 🔵 *旧PHP index.php + DBImgbbs::InsertImgbbs/UpdateInsertImgbbs より*

**私は** 投稿者 **として**
**タイトルと本文を入力し、画像を添付して投稿したい**
**そうすることで** 自分の表現を掲示板に残せる

**関連要件**: REQ-003, REQ-004, REQ-005, REQ-006, REQ-202, EDGE-101, EDGE-102, EDGE-104

**詳細シナリオ**:
1. トップページの投稿フォームに「タイトル」「本文」を入力する
2. 「画像」フィールドからjpg/gif/pngファイルを選択する（任意）
3. 「投稿する」ボタンを押す
4. サーバ側でバリデーションが行われ、合格すると `post` テーブルにレコードが追加される
5. 画像が添付されていれば `img/uploads/{id}.{ext}` に保存され、レコードの `image` カラムが更新される
6. 成功メッセージが表示され、投稿一覧に反映される

**前提条件**:
- タイトルが1〜50文字、本文が0〜500文字、画像（あれば）が許可MIME・5MB以下

**制約事項**:
- 画像添付は任意（空でも投稿可能）

**優先度**: Must Have

### ストーリー 2.2: バリデーションエラーで再入力する 🔵

**信頼性**: 🔵 *旧PHP index.php のエラーメッセージ機構 + ヒアリングより*

**私は** 投稿者 **として**
**入力に不備があった場合、何が悪かったか分かるメッセージと、入力済みの値を保持した状態のフォームを見たい**
**そうすることで** 最初から入力し直さなくて済む

**関連要件**: REQ-201, NFR-202, EDGE-001, EDGE-002, EDGE-101, EDGE-102, EDGE-103

**詳細シナリオ**:
1. タイトルが空、または51文字以上で投稿する
2. または本文が501文字以上で投稿する
3. または許可されていない形式の画像で投稿する
4. または5MBを超える画像で投稿する
5. サーバが400相当のレスポンスを返し、エラーメッセージとともに同じ画面を再表示
6. 入力済みのタイトル・本文は保持されている（画像入力は除く＝ブラウザ仕様上保持できない）

**前提条件**: なし

**優先度**: Must Have

**備考**: 旧PHPでは入力値の保持はしていなかったが、学習として実装する。

## エピック3: 投稿の編集

### ストーリー 3.1: 編集画面を開いて既存値を確認する 🔵

**信頼性**: 🔵 *旧PHP admin_edit.php 38-43行 より*

**私は** 投稿者（or 掲示板管理担当） **として**
**特定の投稿の編集画面で、現在のタイトル・本文・画像を確認したい**
**そうすることで** 何を変更するか判断できる

**関連要件**: REQ-008, REQ-007

**詳細シナリオ**:
1. 投稿一覧の各行にある「編集」ボタンを押す
2. `/posts/{id}/edit` のような編集ページに遷移
3. タイトル・本文の入力欄に現在の値が初期表示され、画像は現在のものがプレビュー表示される

**優先度**: Must Have

### ストーリー 3.2: 投稿を編集して更新する 🔵

**信頼性**: 🔵 *旧PHP DBImgbbsAdmin::UpdateImgbbs + ヒアリング Must Have より*

**私は** 投稿者 **として**
**既存投稿のタイトル・本文・画像を変更したい**
**そうすることで** 後から内容を修正できる

**関連要件**: REQ-009, REQ-104

**詳細シナリオ**:
1. 編集画面で値を変更（タイトル/本文/画像のいずれか）
2. 「登録」ボタンを押す
3. JS の confirm で確認、OKでサーバへPOST送信
4. サーバ側でバリデーション → DB更新（`title`、`text`、必要なら `image` と `update_date`）
5. 新しい画像が選択されていれば `img/uploads/{id}.{ext}` を上書き保存
6. 成功メッセージとともに一覧画面に戻る

**優先度**: Must Have

### ストーリー 3.3: 投稿から画像だけを削除する 🟡

**信頼性**: 🟡 *旧PHP admin_edit.php にチェックボックスは存在するが処理は未実装。妥当な拡張*

**私は** 投稿者 **として**
**投稿は残したまま添付画像だけを取り除きたい**
**そうすることで** 不適切になった画像のみを排除できる

**関連要件**: REQ-103

**詳細シナリオ**:
1. 編集画面の「画像を削除」チェックボックスをONにして「登録」
2. サーバ側で該当投稿の `image` を NULL に更新
3. `img/uploads/{id}.{ext}` のファイルを物理削除
4. 一覧に戻ると、その投稿には画像が表示されない

**優先度**: Should Have

## エピック4: 投稿の削除

### ストーリー 4.1: 確認の上で投稿を削除する 🔵

**信頼性**: 🔵 *旧PHP admin_list.php msgDelete + ヒアリング Must Have より*

**私は** 投稿者 **として**
**不要になった投稿を削除したい**
**ただし誤操作で消えるのを防ぐため確認ダイアログを挟みたい**
**そうすることで** 安全に投稿を削除できる

**関連要件**: REQ-007, REQ-010, REQ-011, REQ-102, NFR-105, NFR-203, EDGE-003

**詳細シナリオ**:
1. 投稿一覧の各行にある「削除」ボタンを押す
2. ブラウザの確認ダイアログで「IDが「N」のデータを削除します。よろしいですか？」と表示
3. OKを選ぶとサーバへ POST `/posts/{id}/delete` のようなリクエスト
4. 該当レコードを削除し、画像ファイルも物理削除
5. 一覧画面に戻ると該当投稿が消えている

**前提条件**:
- 削除対象のIDが存在すること（存在しなければ404）

**優先度**: Must Have
