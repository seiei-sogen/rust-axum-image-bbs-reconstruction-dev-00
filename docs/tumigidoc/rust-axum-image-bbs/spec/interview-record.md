# rust-axum-image-bbs ヒアリング記録

**作成日**: 2026-05-22
**ヒアリング実施**: step4 既存情報ベースの差分ヒアリング

## ヒアリング目的

shiyou.md（プロジェクトメモ）には学習目的・元になるPHP画像掲示板の場所・最小要件（CRUD、認証なし）しか書かれていなかったため、Rust側の技術スタック・スコープ・非機能要件を明確化するためのヒアリングを実施した。

## 質問と回答

### Q1: 作業規模

**質問日時**: 2026-05-22
**カテゴリ**: スコープ調整
**背景**: 学習用かつZenn記事化を伴うため、フル機能開発と軽量開発のどちらに寄せるかで成果物の粒度が変わる。

## ヒアリング結果サマリー

### 確認できた事項

- 技術スタック: axum + sqlx + SQLite + Askama + tracing + Bootstrap
- 画像はローカル `img/uploads/` 配下、5MB 上限、jpg/gif/png のみ
- 投稿一覧は1ページ20件のページネーション付き
- バリデーション規則は旧PHP版に準拠
- 削除は確認ダイアログ必須
- テストとDockerをスコープ内に含める
- コメントは初学者向け日本語・詳細
- ローカル + Docker 起動まで（本番デプロイは対象外）

### 追加/変更要件（旧PHPから）

- **追加**: ページネーション、画像サイズ上限、画像削除（チェックボックス対応）、画像の孤児ファイル防止
- **変更**: DB を MySQL から SQLite、削除リクエストを GET → POST
- **改善**: バリデーションエラー時の入力値保持、tracing 構造化ログ

### 残課題（kairo-design 以降で詰める）

- 具体的なルーティング設計（URL設計、HTTPメソッド）
- DB マイグレーションファイルの初期構成
- Askama テンプレートの分割粒度（layout / partials など）
- エラー型の設計（`thiserror` 等の採用可否）
- Zenn記事のステップ割の詳細（kairo-tasks で決定）

### 信頼性レベル分布

**ヒアリング前**（shiyou.md のみ参照時）:
- 🔵 青信号: 約3項目（CRUD全部・認証なし・管理者なし）
- 🟡 黄信号: 不明（spec が薄い）
- 🔴 赤信号: 推測になる項目が多数

**ヒアリング後**:
- 🔵 青信号: 大幅増加（28件以上）
- 🟡 黄信号: 設計判断に依存する項目（16件程度）
- 🔴 赤信号: ほぼ消滅（オプション要件 REQ-301 のみ）
